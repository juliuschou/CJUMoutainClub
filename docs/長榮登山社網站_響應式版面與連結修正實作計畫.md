# 長榮登山社網站－響應式版面與連結修正實作計畫

## Context

依 `docs/長榮登山社網站_響應式版面與連結修正需求.md` 修正目前 768–1023px 仍使用橫向時間軸、320px 頁首擁擠、導覽缺少 active state，以及時間軸卡片看似可點擊但實際只更新下方預覽等問題。實作需保留單一時間軸資料／DOM、既有 `docs/stories/` 來源、顯式 story mapping、WebP 建構流程與 Next.js static export。

目前僅完成規劃，尚未建立 branch 或修改程式碼。開始實作時，第一個動作會從 `main` 建立 `fix/responsive-timeline-links`。需求文件與其現有未追蹤狀態不會在建分支時被變更。

## Success criteria

- `<1024px` 使用垂直時間軸，`>=1024px` 使用可辨識、可滾輪／觸控板／拖曳的橫向時間軸。
- 320px–1920px 不產生整頁水平捲動；只有桌面時間軸及真正需要的表格容器自行承接水平 overflow。
- 行動／平板頁首為可換列的品牌列＋導覽列；副標題在可用空間保留；導覽觸控區至少 44px。
- Header 固定路由為 `/timeline/`、`/preface/`、`/afterword/`、`/about/`，目前頁面具有可見 active state 與 `aria-current="page"`。
- 每個有效故事節點的整張卡片都是單一 Next `<Link>`，href 為 `/story/${storyId}/`；無故事、取消或無效 ID 不建立連結，DOM 不出現巢狀互動元素或 `/story/undefined/`。
- 桌面仍保留下方故事預覽：卡片 hover／focus 更新選取預覽；原生 Link 點擊直接前往故事頁。初始預覽選第一個有效故事，不再預設無故事節點。
- 37 個故事均由 `generateStaticParams()` 匯出成 `out/story/{storyId}/index.html`，直接開啟／重新整理正常。
- 既有來源與生成規模不變：39 Markdown、37 stories、44 activity rows、45 timeline nodes、248 media references。

# Implementation plan

## 1. 建立分支並記錄可稽核工作項目

- 執行 `git switch -c fix/responsive-timeline-links`，確認起點與未追蹤需求文件。
- 在 `tasks/todo.md` 追加本次 checklist、驗收條件、Working Notes、medium-risk／rollback 區塊；不改寫舊紀錄，也不把舊紀錄當成目前程式已具備的功能。
- 先跑基線 `content:check`、typecheck、lint、tests，保存既有失敗（若有）後才開始修改。

## 2. 統一 route 與 Header active state

- 新增 `src/lib/routes.ts`：集中產生尾端斜線的故事 route，僅接受既有 ASCII slug 規則；無效值回傳 `null`，供所有 UI 安全地決定是否渲染 Link。
- 將 `src/content/site.ts` 的固定導覽路由改成需求指定的尾端斜線格式，並稽核 Header、Footer、首頁、前言、404、故事返回／前後篇等內部 `Link`，統一使用固定 route 或 story route helper。
- 新增小型 Client Component `src/components/site-nav.tsx`，用 App Router `usePathname()` 正規化尾端斜線後做 exact match；`src/components/site-header.tsx` 保持主要結構，改用此元件輸出 active class 與 `aria-current="page"`。故事頁不誤標示為時間軸目前頁。
- 新增 Header／route helper 測試，覆蓋四個 href、`/timeline` 與 `/timeline/` 正規化、唯一 active item、無效 storyId 防護。

## 3. 重整 Timeline 卡片語意，但保留單一 DOM 與桌面預覽

修改 `src/components/timeline/timeline-explorer.tsx`：

- 繼續以同一份 `nodes`、同一組 `<section><ol><li>` 同時支援所有 breakpoint。
- `hasStory && getStoryHref(storyId)` 的節點以整張單一 `<Link className="timeline-node">` 呈現，日期、標題、照片數量與明確「閱讀故事」提示都位於同一 hit area；focus／pointer enter 更新 selected preview，原生 click/Enter 導頁。
- 無故事、取消或無效 ID 節點使用非互動卡片，顯示「僅有活動紀錄／尚無遊記」及取消備註，不加入 tab order、hover cursor 或假 href。
- Link 不使用 `aria-pressed`；改以 `data-selected`、可見的「目前預覽」文字／標記、邊框與陰影共同表示 selected，避免只靠顏色。
- 初始 selected node 改為第一個合法故事；preview 中的「閱讀完整故事」仍使用相同 route helper。
- 年份跳轉保留 button，但調整目標 focus／scroll offset，使 sticky header 不遮住年份；時間軸容器的 aria-label 改為不假設所有 viewport 都能水平捲動。
- 桌面 track 加入最小化的 wheel-to-horizontal 與 pointer-drag 行為；以 drag threshold 和 click capture 避免拖曳後誤觸故事 Link，並保留原生 scrollbar、scroll-snap、觸控板與鍵盤焦點。

更新 `tests/components/timeline-explorer.test.tsx`，驗證：

- 故事卡完整 href、同一 Link hit area、focus 後預覽更新、無 nested anchor/button。
- 無故事／取消／無效 ID 沒有 Link，也不產生 undefined route。
- selected 狀態有非色彩提示；年份跳轉與密度控制仍可鍵盤操作。
- wheel／drag 只捲動 track，drag 不觸發導航。

## 4. 以 Mobile First 對齊 1024 breakpoint

在 `src/app/globals.css` 做局部重整，不全面改版：

- 將 Header 與 Timeline 的 base 規則設為手機／平板版，再以 `@media (min-width: 1024px)` 啟用桌面單列 Header、橫向 timeline、compact density 與雙欄 preview；移除目前 760px 才切垂直 timeline 的落差。
- 以共享 CSS custom properties 定義垂直線位置、node 中心與卡片 gutter，確保年份、節點、線與卡片對齊；裝飾線／節點使用 `pointer-events: none`。
- 主要 shell 使用約 16px（手機）、24px（768+）、48px（1024+）留白，1440+ 限制約 1600px 並置中；用 `min-width: 0`、正常換行與容器寬度修正根因，不用全域 `overflow-x: hidden` 掩蓋問題。
- 行動／平板 Header 使用兩列，導覽自然換列、每個 Link 至少 44×44px；副標題預設可見，只在最窄且確實不足時隱藏。
- 年份快速導覽改為自然換列，不讓整頁或導覽列成為不必要的水平滑動區。
- 桌面 timeline 保留可見 scrollbar、`overscroll-behavior` 與 scroll snap；page 本身不隨 track 變寬。
- 加入 `scroll-padding-top`／`scroll-margin-block-start`，避免 sticky Header 遮住年份或返回錨點。
- 保留既有 image containment、focus-visible、reduced-motion、forced-colors 與語意表格的局部 scroll container；調整 story metadata、pagination、Lightbox footer/button，使 320px 可換行且觸控目標至少 44px。
- 不重排 Markdown 為複雜雙欄；故事正文維持合理閱讀寬度與既有圖片順序，桌面雙欄敘事由 timeline selected preview 繼續承擔。

## 5. 補強故事頁與 Lightbox accessibility

- `src/components/evidence-lightbox.tsx` 補上明確 modal 語意，保留 showModal、Escape、左右鍵、focus loop 與關閉後焦點還原。
- 強化 `tests/components/evidence-lightbox.test.tsx`：實際斷言開啟焦點、`aria-modal`、ArrowLeft/Right 邊界、Tab loop、Escape 後 `document.activeElement` 回到照片 trigger。
- 新增 story route 測試，確認 `dynamicParams === false`、`generateStaticParams()` 與 generated stories 集合完全一致（37 IDs），未知 ID 仍走 `notFound()` 防護。

## 6. 新增可重複的 static export link checker

- 新增 `scripts/check-static-links.ts`，以 Node 內建 fs/path/url 掃描 `out/**/*.html` 的 `href`、`src` 與 `srcset`：忽略外部／mailto／tel／data／純 fragment，去除 query/hash，依來源頁解析相對 URL，並驗證 route `index.html`、`/_next` 與 `/media` 資產存在。
- checker 明確拒絕 `/story/undefined/`、空 story segment、解碼後逃出 `out/` 的 path；錯誤輸出包含來源 HTML、原始 URL、預期目標，並以 non-zero exit 結束。
- 將解析與檔案驗證拆成可測純函式，新增 `tests/scripts/check-static-links.test.ts` 覆蓋 trailing slash、relative URL、query/hash、資產、外部連結、missing target、undefined story 與 traversal。
- `package.json` 新增 `check:links`、`test:e2e` 與串接 build/link-check 的 export verification script；不改變 `content:clean -> next build` 的既有內容生成順序。

## 7. Playwright 響應式與連結驗收

利用既有 `@playwright/test`，新增 `playwright.config.ts` 與 `tests/e2e/responsive-links.spec.ts`；以 `npm run preview` 提供 `out/`，並允許 `BASE_URL` 指向 Cloudflare Pages 後重跑同一套 smoke tests。

逐一覆蓋需求矩陣：320×568、360×800、375×812、390×844、412×915、768×1024、1024×768、1280×720、1440×900、1920×1080。驗證：

- document/body 無整頁水平 overflow，Header 導覽無重疊且 touch target 合格。
- `<1024` 垂直、`>=1024` 橫向；桌面 track 自身可 wheel／drag 並 snap，不帶動 page。
- 所有 37 個故事卡 href 合法，8 個無故事節點無 anchor；點擊卡片文字、空白與照片數量皆到相同故事 route。
- Tab/Enter、active nav、年份跳轉 sticky offset、browser back、代表性故事直接開啟與 reload、圖片 containment、Lightbox 開關與焦點還原。
- 收集 console error、page error 與 failed same-origin requests，作為測試失敗。

`next-dev-loop` 目前不列為驗收證據，因專案 Next.js 16.2.12 與現有環境不符合該技能的 16.3+/agent-browser 前置條件；真實瀏覽器證據改由 Playwright static preview 提供。

## 8. CI 與部署邊界

- 新增 `.github/workflows/verify.yml`，執行 `npm ci`、content check、typecheck、lint、Vitest、build、static link checker，以及單一 Chromium 的 Playwright suite，使 broken link 能實際阻擋 CI。
- 不修改 Cloudflare 專案、credentials 或 `npm run deploy`；正式部署仍是 outward-facing 動作，需另行明確批准。
- 部署後以 `BASE_URL=<Cloudflare Pages URL> npm run test:e2e` 重跑直接路由／reload／連結 smoke，並將結果記入 `tasks/todo.md`。

# Risk and rollback

- **Risk: medium.** 主要影響 Header route awareness、timeline 互動語意、1024 breakpoint、瀏覽器測試與 CI；不影響史料與資料 mapping。
- Timeline 由 button-selection 改為 native Link navigation 是可見行為變更；以 hover/focus preview、完整 hit area、browser back E2E 覆蓋。
- Pointer drag 可能與 Link click 衝突；以移動 threshold、click-capture regression tests 與真實瀏覽器 drag test 控制。
- `usePathname()` 只隔離在小型 Client Component，避免擴大 hydration 範圍。
- Link checker 若誤判，只修正 checker 與 fixtures，不改生成輸出迎合錯誤規則。
- 可按 checkpoint 回復 UI/CSS、checker、Playwright/CI 檔案；任何 rollback 都不碰 `docs/stories/`、story map、overrides 或生成媒體。
