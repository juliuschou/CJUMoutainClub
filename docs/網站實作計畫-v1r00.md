# 長榮登山社校友會遊記網站實作計畫 v1r00

## Context

依據 `docs/網站開發需求規格書-v1r00.md`，將目前僅由 Markdown 與舊照片構成的遊記資料，建成可靜態匯出的 Next.js 網站。核心成果是：以時間軸呈現全部活動、提供完整遊記閱讀與照片 Lightbox、呈現前言／後記／關於頁，並保留原始資料的歷史缺漏與取消活動。

已確認資料現況與規格有差異：實際共有 37 篇遊記、39 個 Markdown、248 個媒體檔，活動年表有 44 筆且缺序號 24，取消活動實為 5 筆。依使用者決定，將現有「92年10月／合歡北峰-天巒池縱走」補為序號 24，因此網站呈現 45 個時間軸節點、37 篇故事，並清楚註記序號 24 為依現存遊記補入、原始年表未列。

本計畫核准後先另存為 `docs/網站實作計畫-v1r00.md`；程式實作另待使用者指示。

## Scope and acceptance criteria

- 建立 Next.js App Router、TypeScript、Tailwind CSS 靜態網站。
- 路由包含 `/`、`/timeline`、`/story/[storyId]`、`/preface`、`/afterword`、`/about`。
- 產生 45 個時間軸節點，其中 37 個具完整遊記；5 個取消活動具明確取消狀態。
- 解析並正確渲染 37 篇 Markdown 的標題、段落、粗體、子章節、表格與圖片。
- 248 個來源媒體均完成關聯；WMF 轉為瀏覽器可用格式；裝飾性 40×40 PNG 不列入 Lightbox。
- 故事圖片可鍵盤操作並支援 Lightbox 的 Esc、左右方向鍵、焦點移入與還原。
- 桌面、平板、手機版均可用，色彩對比與互動符合基本 WCAG AA。
- `next build` 成功產生可直接由靜態主機提供的 `out/`。
- Lighthouse 效能目標至少 80。

## Recommended implementation

### 1. 建立專案基礎

新增：

- `package.json`、`package-lock.json`
- `next.config.ts`、`tsconfig.json`、`eslint.config.mjs`
- `postcss.config.mjs`
- `src/app/layout.tsx`、`src/app/globals.css`
- `.gitignore`

技術選擇：

- 使用支援已安裝 `next-dev-loop` 的 Next.js 16.3+、React 19。
- Tailwind CSS 4 與 `@tailwindcss/postcss`。
- `react-markdown` + `remark-gfm` 渲染遊記與表格。
- `unified`、`remark-parse`、`remark-gfm` 作建構期 AST 解析。
- `sharp` 產生 WebP 衍生圖；單一 WMF 透過 ImageMagick `magick` 先轉成 PNG。
- Vitest 測試資料解析與互動元件；避免非必要的動畫與 UI 套件。

`next.config.ts` 設定：

- `output: 'export'`
- `trailingSlash: true`
- `images.unoptimized: true`（實際圖片已由建構腳本預先處理）
- 不設定 `basePath`/`assetPrefix`，先以根路徑靜態部署為預設。

### 2. 建立可稽核的內容對應表

新增：

- `src/content/story-map.ts`
- `src/content/overrides.ts`
- `src/lib/types.ts`

`story-map.ts` 明列序號 0–44 的 ASCII `storyId`、來源目錄與是否具遊記，不使用地點模糊比對。序號 24 明列為：

- `storyId: '92-10-hehuan-north-peak'`
- `sourceDirectory: '92年/10月/合歡北峰-天巒池縱走'`
- `source: 'story-only'`
- 顯示註記「原始年表缺號，依現存遊記補入」。

`overrides.ts` 集中維護：

- 不規則或多作者文章的作者清單。
- 特殊地點、標題及摘要修正。
- `image65.png` 的裝飾性分類。
- 其他無法可靠自動推導的編輯資料。

### 3. 實作內容與圖片建構流程

新增：

- `scripts/build-content.ts`
- `src/generated/stories.json`
- `src/generated/timeline.json`
- `src/generated/evidence.json`
- `src/generated/preface.json`
- `src/generated/afterword.json`
- `public/media/<storyId>/...`（自動產生）

流程：

1. 掃描 `docs/stories/<年>/<月>/<故事>/<故事>.md`，排除前言與後記。
2. 從目錄取得 canonical 民國年／月；`00月` 轉為 `null`。
3. 以 AST 取得 H1、日期 blockquote、段落、表格與圖片順序。
4. 解析 `前言.md` 表格，只接受數字序號列，跳過分隔列與重複表頭，保留 44 筆原表資料。
5. 合併顯式 story map，加入序號 24，生成 45 個時間軸節點。
6. 作者採「保守的最佳努力解析 + 人工覆寫」，不以單一 regex 猜測全部文章。
7. 摘要以 Markdown 段落為單位，略過標題、日期、作者標記、純圖片與 `【接下頁】`，取第一個有意義段落；無內容時退回年表備註或標題。
8. 僅移除空 `<style></style>` 與頁面分頁殘留，保留其他原文結構。
9. 依 Markdown 出現順序建立 evidence；不依 `imageN` 數字排序。
10. 驗證每個媒體引用存在，再產生縮圖、閱讀圖與原尺寸上限圖；不放大低解析來源。
11. 將 WMF 先轉為 PNG 再進入相同圖片流程；缺少 ImageMagick 時以清楚錯誤中止建構。
12. 產生前後故事導航；取消／無遊記節點不產生故事路由。

重要資料不變量：

- 原始年表：44 筆，序號集合為 0–23、25–44。
- 補入後時間軸：45 節點。
- 遊記：37 篇。
- 取消活動：序號 12、22、27、30、42，共 5 筆。
- 原始媒體：248 個引用／248 個檔案；239 JPEG、8 PNG、1 WMF。
- 無照片遊記：7 篇。

### 4. 建立共用版型與設計系統

新增代表性檔案：

- `src/components/site-header.tsx`
- `src/components/site-footer.tsx`
- `src/components/photo-frame.tsx`
- `src/components/page-header.tsx`
- `src/components/responsive-table.tsx`

在 `globals.css` 建立深林綠、山岩褐、晨霧灰、米白紙色、秋金等 CSS variables；使用漸層製作低成本紙張紋理。根版型設定 `lang="zh-Hant"`，中文以 Noto Serif TC、英文／數字以 Inter 並保留系統字型 fallback。

Server Component 為預設；只將時間軸選取、行動選單與 Lightbox 做成 Client Components，以減少 hydration 與序列化資料量。

### 5. 實作頁面

#### 首頁 `src/app/page.tsx`

- 使用固定精選照片，不做 MVP 輪播。
- 顯示網站標題、副標題與「進入時間軸」。
- 提供前言、後記、關於連結與簡短典藏說明。

#### 時間軸 `src/app/timeline/page.tsx`

元件：

- `src/components/timeline/timeline-explorer.tsx`
- `timeline-node.tsx`
- `story-preview.tsx`
- `year-navigation.tsx`

行為：

- 桌面／平板為水平捲動；手機改為垂直時間軸。
- 顯示一般、重要、取消、照片豐富四種狀態。
- 年份可快速跳轉，提供總覽／詳細密度切換。
- 點擊或 Enter/Space 開啟摘要卡，最多顯示三張縮圖。
- 取消活動只顯示原因；有故事者提供完整閱讀連結。
- 僅 45 節點，不引入虛擬化依賴；以 `content-visibility` 與 lazy image 控制成本。

#### 故事頁 `src/app/story/[storyId]/page.tsx`

- `generateStaticParams()` 產生 37 個靜態路由，`dynamicParams = false`。
- `generateMetadata()` 產生標題與摘要。
- 顯示日期、地點、作者、參加人數與原始年表註記。
- `StoryMarkdown` 以 `react-markdown` + GFM 渲染，提供響應式表格與自訂圖片 renderer。
- 圖片按鈕以事件代理開啟單一 Lightbox，避免每張圖片各自建立狀態。
- 無照片故事顯示中性的「本篇無留存照片」狀態。
- 底部顯示前一篇／後一篇遊記。

#### Lightbox

新增 `src/components/evidence-lightbox.tsx`：

- `role="dialog"`、`aria-modal="true"`。
- 開啟時移入焦點，關閉時還原至觸發圖片。
- Esc 關閉、左右方向鍵切換、明確的上一張／下一張按鈕。
- 裝飾性圖片不進入 Lightbox，使用空 alt。
- 一般圖片 alt 使用「活動名稱，第 N 張照片（原始檔名）」；不虛構照片內容。

#### 前言、後記、關於

- `src/app/preface/page.tsx`：指導老師文字、資料缺漏說明、完整響應式年表；有故事列可跳轉，取消／無故事列有文字狀態。
- `src/app/afterword/page.tsx`：全文、出版資訊、撰文與攝影名單。
- `src/app/about/page.tsx`：時間證據卡理念、資料來源、靜態技術架構，以及序號 24／資料數量差異的透明說明。

### 6. 測試與資料驗證

新增代表性測試：

- `tests/content/preface-table.test.ts`
- `tests/content/story-build.test.ts`
- `tests/content/evidence.test.ts`
- `tests/components/timeline-explorer.test.tsx`
- `tests/components/evidence-lightbox.test.tsx`

驗證：

- 表格重複表頭不會被當作資料。
- 44 筆原始活動與 45 個補入後節點均符合預期。
- 37 篇遊記均且只被對應一次，ASCII slug 唯一。
- 5 筆取消活動與 8 筆原表無故事活動正確。
- 248 個來源引用全數存在，WMF 不會出現在輸出 HTML。
- 兩種 Markdown 表格可渲染。
- 圖片順序依 Markdown occurrence。
- Lightbox 的開啟、關閉、鍵盤導航、邊界按鈕與焦點還原正確。
- 時間軸節點支援鍵盤操作，取消／無故事狀態不提供錯誤連結。

## Execution checkpoints

1. **Checkpoint A — Bootstrap and baseline**
   - 更新 `tasks/todo.md`，記錄 acceptance criteria、風險、依賴與 working notes。
   - 建立 Next.js 骨架與空路由。
   - 確認 `next dev --turbopack` 可啟動。

2. **Checkpoint B — Content pipeline**
   - 完成顯式 mapping、Markdown/table parser、圖片處理與完整資料驗證。
   - 在 UI 開發前先讓所有 corpus invariants 測試通過。

3. **Checkpoint C — Pages and interactions**
   - 實作首頁、時間軸、故事、前言、後記、關於與 Lightbox。
   - 完成響應式、鍵盤操作與錯誤／空狀態。

4. **Checkpoint D — Full verification**
   - 執行靜態檢查、單元測試、建構、實際瀏覽器檢查與 Lighthouse。
   - 將結果、未能執行項目與指令寫入 `tasks/todo.md` Results。

預計執行：

```bash
npm run content:check
npm run typecheck
npm run lint
npm test
npm run build
git diff --check
```

執行期驗證：

1. 啟動 `npm run dev`。
2. 依已安裝的 `next-dev-loop` 驗證 `/_next/mcp`：路由、編譯問題、執行期錯誤與頁面 metadata。
3. 使用 `agent-browser` 檢查首頁、時間軸、多照片故事、無照片故事、前言、後記、關於。
4. 在桌面／平板／手機 viewport 測試時間軸、表格、圖片與 Lightbox。
5. 以鍵盤完成時間軸節點選取、故事連結、Lightbox 開關與圖片切換。
6. 以靜態伺服器提供 `out/` 後重跑主要 smoke tests，證明不依賴 Next.js server。
7. 執行 Lighthouse，確認效能至少 80，並記錄 Accessibility、Best Practices 與 SEO 結果。

## Risk and rollback

- **資料對應風險（中）**：所有 alias 與序號只在 `story-map.ts`／`overrides.ts` 維護；遇未映射或重複資料即中止建構。
- **序號 24 歷史差異（中）**：以 `source: 'story-only'` 明確標示，不改動原始前言 Markdown；如需回復原表模式，只調整 mapping/presentation policy。
- **舊圖片格式與檔案量（中）**：原始 `docs/stories` 永不改寫；所有衍生檔可刪除重建。WMF 轉檔失敗時安全中止，不靜默遺漏。
- **部署路徑（低）**：目前採根路徑；未來確定 GitHub Pages 子路徑時，再集中調整 `basePath`、`assetPrefix` 與連結驗證。
- **字型／外部下載（低）**：保留本機系統字型 fallback；若建構環境不能下載 Google Fonts，改為 vendored fonts 而不改頁面架構。
- **Rollback**：依 Bootstrap、Content pipeline、UI 三個薄切片分段回退；來源 Markdown 與照片不受影響。
