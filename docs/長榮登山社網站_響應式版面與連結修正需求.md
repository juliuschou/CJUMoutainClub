# 長榮登山社校友會網站－響應式版面與連結修正需求

## 一、調整目標

調整網站的 Responsive Web Design，使網站可在桌面、筆記型電腦、平板與行動裝置上正常呈現。

本次調整需達成：

1. 不同螢幕尺寸皆可正常閱讀與操作。
2. 桌面版維持橫向時間軸的敘事方式。
3. 行動版改用垂直時間軸，避免橫向捲動。
4. 修正行動版時間軸故事卡及導覽列連結無法正常跳轉的問題。
5. 保持現有內容建構流程、資料來源與靜態匯出架構不變。
6. 不直接修改 `docs/stories/` 中的原始史料。

---

## 二、目前問題

### 2.1 桌面版

桌面版目前採用：

- 頁首左側顯示網站標誌與名稱。
- 頁首右側顯示主要導覽連結。
- 時間軸以水平方向排列。
- 選取時間軸故事後，下方顯示故事內容與照片。
- 時間軸區域可水平捲動。

桌面版整體方向可保留，但需改善：

- 時間軸捲動操作。
- 卡片點擊範圍。
- 不同桌面寬度下的節點間距。
- 選取狀態與鍵盤操作。
- 內容區圖片排列。

### 2.2 行動版

行動版目前已顯示為垂直時間軸，但存在以下問題：

1. 頁首高度較大，導覽連結排列較擁擠。
2. 網站副標題在行動版未顯示，桌面與行動版資訊不一致。
3. 時間軸年份、節點、卡片與垂直線的對齊需改善。
4. 卡片寬度與左側時間軸節點之間的距離不一致。
5. 部分故事卡或文字看起來可點擊，但實際連結沒有正常運作。
6. 缺少明確的點擊提示，例如「閱讀故事」。
7. 頁面不可出現整體水平捲動。
8. 固定或黏著式頁首不可遮住時間軸年份或內容。

## 三、響應式版面規則

### 3.1 Breakpoint 規則

使用 Tailwind CSS Breakpoint，至少支援以下範圍：

| 裝置類型 | 寬度 | 時間軸模式 |
|---|---:|---|
| 小型行動裝置 | 320px–479px | 垂直時間軸 |
| 一般行動裝置 | 480px–767px | 垂直時間軸 |
| 平板 | 768px–1023px | 垂直時間軸或加寬垂直時間軸 |
| 桌面 | 1024px 以上 | 橫向時間軸 |
| 大型桌面 | 1440px 以上 | 橫向時間軸，限制主要內容最大寬度 |

不得只針對某一支手機或單一解析度寫死尺寸。

### 3.2 全域版面

所有頁面必須符合：

- 使用 Mobile First CSS。
- `body` 不得產生非預期的水平捲動。
- 主要內容區應設定合理的 `max-width`。
- 左右留白依裝置尺寸調整。
- 圖片不得超出父層容器。
- 長標題必須正常換行。
- 不可使用大量固定像素寬度。
- 除桌面版時間軸容器外，不得使用 `overflow-x: auto` 隱藏版面問題。

建議主要內容寬度：

```text
行動版：左右各 16px
平板版：左右各 24px
桌面版：左右各 48px
大型桌面：max-width 約 1600px，置中顯示
```

## 四、頁首與導覽列需求

### 4.1 桌面版頁首

桌面版應維持：

- 左側：標誌、網站名稱、副標題。
- 右側：時間軸、前言、後記、關於。
- 所有導覽項目垂直置中。
- 頁首高度固定且不因文字換行而跳動。

### 4.2 行動版頁首

行動版調整為兩列：

第一列：

- 左側顯示標誌。
- 右側顯示網站名稱。
- 副標題可顯示在名稱下方，或在極小螢幕隱藏。

第二列：

- 顯示主要導覽。
- 導覽項目間距一致。
- 文字不可互相重疊。
- 320px 寬度仍須可操作。

導覽項目可採以下其中一種方式：

1. 優先方案：允許導覽項目自然換列。
2. 替代方案：導覽列自身可水平滑動，但不得造成整個頁面水平滑動。
3. 當導覽項目未來增加時，可改為漢堡選單。

目前只有四個項目，建議先保留直接顯示，不必立刻加入漢堡選單。

### 4.3 導覽列連結

導覽列路由固定為：

```text
時間軸 → /timeline/
前言   → /preface/
後記   → /afterword/
關於   → /about/
```

目前所在頁面的連結需有明確的 Active State，例如：

- 底線。
- 字重變粗。
- `aria-current="page"`。

## 五、桌面版時間軸需求

螢幕寬度大於或等於 1024px 時，使用橫向時間軸。

### 5.1 水平時間軸

- 年份按照時間順序由左至右排列。
- 活動節點需與年份正確對齊。
- 每個節點下方顯示月份、標題及照片數量。
- 時間軸區域允許水平捲動。
- 時間軸水平捲動不得帶動整個頁面。
- 建議加入 `scroll-snap`，讓節點停靠更自然。
- 滑鼠滾輪、觸控板與拖曳操作皆需可用。
- 不可隱藏捲動能力而讓使用者不知道後方仍有內容。

### 5.2 故事卡狀態

故事卡需支援：

- 預設狀態。
- Hover 狀態。
- Focus 狀態。
- Active／Selected 狀態。
- 無故事內容的時間節點狀態。

選取中的故事卡可使用：

- 背景色。
- 邊框。
- 節點顏色。
- 陰影。

但不可只依靠顏色表示狀態。

### 5.3 故事內容區

桌面版選取故事後，下方顯示：

- 活動分類或序號。
- 故事標題。
- 時間。
- 地點。
- 人數。
- Markdown 文章內容。
- 活動照片。
- 「閱讀完整故事」連結。

寬螢幕使用兩欄：

```text
左欄：文字內容
右欄：照片與圖庫
```

較窄桌面可切換成單欄。

## 六、行動版時間軸需求

螢幕寬度小於 1024px 時，使用垂直時間軸。

### 6.1 垂直時間軸結構

每個年份應形成獨立區段：

```text
年份
│
├─ 活動節點
│  月份
│  活動標題
│  照片數量
│
├─ 活動節點
│  月份
│  活動標題
│
下一個年份
```

要求：

- 時間軸線固定於內容左側。
- 節點中心與時間軸線中心對齊。
- 年份文字與活動卡片不得被頁首遮住。
- 節點不可壓住文字。
- 卡片右側不得超出螢幕。
- 活動之間需有足夠垂直間距。

### 6.2 行動版故事卡

故事卡應：

- 使用接近可用寬度的全寬卡片。
- 保留左側時間軸節點空間。
- 標題可以換行。
- 照片數量顯示於標題下方。
- 整張卡片具有清楚的點擊回饋。
- 最小觸控高度不得低於 44px。
- Focus 狀態需清楚可見。
- 不可只有標題文字的一小部分可以點擊。

### 6.3 故事內容行為

建議行動版採用以下行為：

- 點擊故事卡後前往獨立故事頁：
  `/story/[storyId]/`
- 不要在時間軸下方一次顯示大量完整文章與照片。
- 返回時間軸時，盡可能保留原本捲動位置。

替代方案：

- 點擊卡片後，在該卡片正下方展開摘要。
- 摘要內提供「閱讀完整故事」連結。

本次建議採用第一種方式，效能、操作與維護均較簡單。

## 七、連結異常修正需求

### 7.1 故事連結格式

所有具有故事內容的時間軸節點，應導向：

```tsx
/story/${storyId}/
```

例如：

```text
/story/94-07-daxueshan-orientation/
```

不得使用：

- 中文資料夾名稱直接組成 URL。
- Windows 路徑分隔符號。
- 相對層級不明確的 `../../story/...`。
- 手動加入 `.html`。
- 只透過 JavaScript `onClick` 跳轉。
- 空字串或 `#` 代替正式路徑。

### 7.2 Next.js 實作要求

內部連結統一使用：

```tsx
import Link from "next/link";
```

範例：

```tsx
<Link href={`/story/${story.storyId}/`}>
  <span>{story.title}</span>
</Link>
```

故事頁需確認：

- 使用 `generateStaticParams()` 產生全部 `storyId`。
- 每個 `storyId` 均存在於靜態輸出。
- `npm run build` 後，`out/story/{storyId}/index.html` 必須存在。
- `storyId` 使用 ASCII slug。
- 不得依賴伺服器端動態路由。

### 7.3 卡片點擊區域

若整張故事卡為連結：

- 最外層使用單一 `<Link>`。
- 不可在 `<Link>` 裡再放另一個 `<a>` 或 `<button>`。
- 不可有透明元素覆蓋連結。
- 裝飾節點應使用 `pointer-events-none`。
- 卡片的 `z-index` 必須高於裝飾背景，但低於必要的固定頁首。
- 點擊文字、空白區、照片數量都應前往相同故事頁。

### 7.4 無故事內容的節點

例如只有活動名稱、沒有對應 Markdown 的節點：

- 不應建立假的故事連結。
- 顯示為不可點擊節點。
- 不顯示 Hover 指標。
- 可顯示「尚無遊記」或「僅有活動紀錄」。
- 不可導向不存在的 `/story/undefined/`。

### 7.5 靜態部署路徑

專案使用：

```ts
output: "export"
trailingSlash: true
```

因此需確認：

- 內部路由與 `trailingSlash` 一致。
- 不可依賴 Next.js Server Redirect。
- 不可依賴 Middleware。
- 不可依賴 Route Handler 動態處理頁面。
- 所有頁面在 Cloudflare Pages 直接重新整理時仍能正常開啟。
- 圖片與 JSON 路徑不得因部署根路徑不同而失效。

## 八、故事頁需求

`/story/[storyId]/` 必須支援所有裝置。

### 行動版

- 單欄顯示。
- 標題、時間、地點與人數不可擠在同一列。
- 圖片使用單欄或雙欄。
- 圖片寬度不得超出畫面。
- Lightbox 關閉按鈕需容易點擊。
- 提供返回時間軸的連結。

### 桌面版

- 文字與圖片可使用兩欄。
- 文章閱讀寬度應限制在合理範圍。
- 圖片保持比例，不可拉伸變形。
- 縮圖應使用建構時產生的適當圖片尺寸。

---

## 九、無障礙需求

至少符合：

- 所有連結可使用 Tab 鍵操作。
- Focus 狀態清楚可見。
- 所有圖片具有適當的 `alt`。
- 裝飾圖片使用空的 `alt=""`。
- 目前頁面使用 `aria-current="page"`。
- 時間軸使用有意義的 HTML 結構，例如 `<ol>` 與 `<li>`。
- 不只使用顏色表示目前選取狀態。
- 最小觸控區域為 44 × 44px。
- 文字與背景應有足夠對比。
- 支援 `prefers-reduced-motion`。
- Lightbox 開啟後需管理鍵盤焦點。

---

## 十、效能需求

- 不得在行動版一次載入所有故事的完整大圖。
- 時間軸僅載入必要的縮圖或 Metadata。
- 故事完整照片應在故事頁載入。
- 圖片必須保留既有 WebP 建構流程。
- 圖片需設定寬度、高度或 `aspect-ratio`，避免版面跳動。
- 非首屏圖片使用 Lazy Loading。
- 不因 Responsive 調整而複製兩份完整時間軸 DOM。
- 若桌面版與行動版使用不同元件，需避免兩份元件同時載入大量內容。

## 十一、測試需求

### 11.1 測試尺寸

至少測試：

```text
320 × 568
360 × 800
375 × 812
390 × 844
412 × 915
768 × 1024
1024 × 768
1280 × 720
1440 × 900
1920 × 1080
```

### 11.2 功能測試

確認：

1. 首頁連結正常。
2. 時間軸連結正常。
3. 前言連結正常。
4. 後記連結正常。
5. 關於連結正常。
6. 每一個有遊記的時間軸節點都能前往正確故事頁。
7. 沒有遊記的節點不會產生錯誤連結。
8. 瀏覽器返回後可回到時間軸。
9. Cloudflare Pages 正式網址直接開啟故事頁不會出現 404。
10. 點擊卡片各個區域都能正確跳轉。

### 11.3 自動化測試

使用既有 Vitest、Testing Library 與 jsdom 增加：

- Header 導覽連結測試。
- Timeline Card `href` 測試。
- 有 `storyId` 與無 `storyId` 的條件測試。
- Active State 測試。
- 鍵盤操作測試。
- 行動版與桌面版元件呈現條件測試。
- 無效 `storyId` 防護測試。

另外新增建構後連結檢查：

1. 讀取 `out/` 下所有 HTML。
2. 收集站內 `href`。
3. 驗證對應的 HTML 或靜態資源存在。
4. 發現 Broken Link 時讓 CI 失敗。

## 十三、建議實作順序

1. 找出目前 Header、Timeline、Timeline Card 與 Story Page 元件。
2. 建立一致的 Responsive Breakpoint 規則。
3. 先修正全域寬度與水平溢位問題。
4. 調整行動版 Header 與導覽列。
5. 分離桌面橫向時間軸與行動垂直時間軸的排版責任。
6. 統一故事卡的連結產生方式。
7. 驗證 `generateStaticParams()` 是否包含全部故事。
8. 檢查 `out/story/` 靜態輸出。
9. 增加元件測試與建構後 Broken Link 檢查。
10. 分別在本機預覽及 Cloudflare Pages 驗證。

## 十四、問題判斷重點

附件中的行動版畫面顯示 Responsive 切換本身已有初步實作，因此不建議全面重寫。較合理的策略是：

1. 保留桌面橫向時間軸。
2. 保留行動垂直時間軸。
3. 統一故事卡資料與連結產生邏輯。
4. 讓桌面版與行動版只負責不同排版，不各自重新組合 URL。
5. 以靜態輸出檔案是否存在作為連結驗收依據。

連結異常不能只靠 CSS 修正，也需同時檢查 `storyId`、`Link href`、`generateStaticParams()`、卡片上方是否有遮罩元素，以及 Cloudflare Pages 的靜態輸出路徑。
